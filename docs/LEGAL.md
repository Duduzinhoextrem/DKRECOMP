# O que pode e o que não pode ir para o GitHub

English: [LEGAL.en.md](LEGAL.en.md)

Estas são as regras técnicas do projeto. Não é aconselhamento jurídico: a lei sobre cópias de segurança, engenharia
reversa e interoperabilidade muda de país para país.

## O que o DKRecomp é

Uma ferramenta que converte, na máquina do usuário, arquivos que ele obteve da própria cópia do jogo. O repositório
guarda só código e documentação do projeto, mais código de terceiros com licença compatível, listado em
`THIRD_PARTY_NOTICES.md`. O jogo convertido nunca sai do computador de quem o converteu.

## Pode ir para o GitHub

| O quê | Exemplos | Observação |
|---|---|---|
| Código e documentação próprios do DKRecomp | `tools/`, `runtime/`, `docs/`, `tests/` | |
| Testes com dados sintéticos | shaders de `tests/native/shaders/`, programas de `tests/diff/` | Feitos pelo projeto, sem bytes do jogo |
| Código de terceiros com licença permissiva | ASTC do LAS Recomp, tradutor do TotK Recomp, layout do deko3d | Só MIT, BSD, ISC, zlib ou Apache-2.0, com o texto da licença e uma linha em `THIRD_PARTY_NOTICES.md` |
| Identificadores de versão | `titles/dkctf/title.toml`: SHA-256, IDs de título e de build, tamanhos | Reconhecem a versão; não permitem reconstruir o jogo |
| Fatos sobre o binário escritos com as nossas palavras | endereços, offsets, IDs de comandos IPC, layout de estruturas, nomes de funções do SDK | Necessários para interoperar. Nunca copie código ou dados do jogo junto |
| Nomes públicos da API NVN | `runtime/gfx/third_party/nvn_procs.inc` | Lista MIT vinda do TotK Recomp |
| Scripts que baixam ferramentas abertas das fontes oficiais | SDL3, Vulkan-Headers | Os arquivos baixados ficam em `toolchain/`, fora do Git |

## Nunca pode ir para o GitHub

| O quê | Exemplos |
|---|---|
| Arquivos do jogo | NSP, XCI, NCA, NSO, NPDM, NACP, tickets, certificados, conteúdo da ExeFS e da RomFS |
| Qualquer coisa derivada do jogo | C gerado (`generated/`), `dkctf.exe`, imagens `.img` dos módulos, `romfs.bin`, shaders traduzidos (`.maxwell`, `.spv`, `.dkrspv`), `pipelines.bin`, capturas `.bmp`, logs e relatórios com conteúdo extraído (`reports/`), a pasta `DKRecomp-Portatil/` |
| Chaves e dados do console | `prod.keys`, `title.keys`, firmware, dados únicos do console |
| Ferramentas de decriptação embutidas | o `nstool` é sempre o do usuário (decisão do projeto, mantida em 2026-11-03) |
| Saves e configurações pessoais | `user_files/saves/`, `config.local.toml` |
| Código GPL ou sem licença | yuzu, versões GPL antigas do Ryujinx, o núcleo do Unicorn. Podem ser estudados ou usados como ferramenta de teste, nunca copiados |
| Arte, logos e músicas do jogo | ícones, telas, trilha sonora extraídos do jogo |

Repositórios que publicaram chaves, ferramentas de extração de chaves ou arquivos de jogos já foram removidos do
GitHub por pedidos de remoção. O DKRecomp evita os dois casos: não guarda chaves nem conteúdo do jogo, e não
implementa decriptação.

## Regras do código

1. O DKRecomp não lê, não guarda e não imprime chaves. O leitor de tickets
   (`tools/dkrecomp/formats/ticket.py`) devolve só identificadores e nunca acessa o bloco da chave de título. O
   launcher pergunta onde estão o `nstool` e o `prod.keys` do usuário e repassa esses caminhos ao `nstool`; o arquivo
   de chaves nunca é aberto pelo DKRecomp.
2. O DKRecomp não decripta nada nem contorna proteções. Ele lê só o que já está em texto claro (cabeçalho PFS0, campos
   públicos do ticket, `.cnmt.xml`) e arquivos que o usuário já extraiu.
3. Nenhuma ferramenta baixa jogos, atualizações, chaves ou firmware.
4. O jogo convertido é de uso pessoal. O C gerado começa com o aviso
   `GENERATED BY DKRecomp - do not edit. Derived from the input binary: keep out of version control.` O executável e
   o pacote portátil também não podem ser compartilhados.
5. *Donkey Kong Country*, *Tropical Freeze* e *Nintendo Switch* são marcas da Nintendo. Não use logos ou
   arte oficial no repositório, e mantenha o aviso de que o projeto não tem afiliação com a Nintendo ou a Retro Studios.

## Antes de cada push

```bash
.venv/Scripts/python tools/check_content.py
git status --short
```

O `check_content.py` confere todos os arquivos rastreados e falha se encontrar uma extensão ou pasta proibida, um
arquivo binário que não esteja na lista de exceções ou um arquivo grande demais. O `.gitignore` já bloqueia as pastas
`game original meu/`, `user_files/`, `SwitchExtract/`, `build/`, `generated/`, `reports/`, `refs/` e `toolchain/`.

Uma coisa não é questão legal, mas fica pública com o push: o nome e o e-mail do autor de cada commit aparecem no
GitHub. Para esconder o e-mail, use o endereço `noreply` que o GitHub oferece nas configurações de e-mail; commits já
feitos continuam com o endereço antigo, a menos que o histórico seja reescrito antes do primeiro push.
